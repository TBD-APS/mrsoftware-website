Security and data privacy

MR Software builds systems with fail-closed defaults: access starts at zero, every change has to be provable, and secrets never touch business code. Here we describe what that means in practice, and how we validate our own work.

Secure by default

Access starts at zero

No agent, tool or user has access until it is explicitly granted. A missing approval or missing evidence blocks the action, never the other way round.

Human approval

Changes with consequences need human approval tied to a specific action. Production changes go through protected environments with owner approval.

Secrets stay in the vault

Configuration refers to Key Vault names, never values. Secrets are never part of agent context, events or browser storage.

Tenants are isolated

State and audit events are partitioned per tenant. Only a minimal index of permission id + tenant id is global.

Tamper-evident audit trail

Approvals and side-effect decisions go into a SHA-256 hash chain. Every read verifies the chain.

Protected environments

Production work runs in environments with a wait timer and a protected branch policy (live: 30 min. owner approval).

Data privacy

MR SAAS'y only processes the data needed to run the system: workflow events, permissions, approvals, audit events and agent performance signals.

DataPurposeNote
Workflow eventsTraceable execution and recoveryAppend-only event stream
Permissions & approvalsAccess controlSplit by tenant, audit-logged
Audit eventsRecord of decisionsSHA-256 chained, cannot be deleted
Agent performance dataRouting and learningAggregated; raw prompts are never logged
MOTOR does not store prompts, secrets or customer payloads. If an event cannot sanitise its content, it is not written with raw data.

As a company we are bound by the General Data Protection Regulation (GDPR). Processing is limited, tied to a purpose and backed by the necessary technical and organisational measures. Contact us at kontakt@mrsoftware.dk with any questions about data protection.
