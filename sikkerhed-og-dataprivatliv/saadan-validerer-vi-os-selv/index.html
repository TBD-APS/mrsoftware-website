The principle: evidence over trust

MR SAAS'y is built on the idea that a system should be able to prove that it works, not just run. That applies to our own development too:

  • No change lands without evidence. A pull request is not done until its tests, analysis and deploy risk check are green.
  • Recovery is conservative. If the history cannot prove that an action is safe to repeat, the system refuses to repeat it automatically.
  • Failure states are visible. The status system separates "not configured" (yellow) from active failures (red), so operators don't mistake an opt-out for a broken service.
  • The numbers are real. Everything on this page is measured, not a target.

Repository protection & environments

Documentation integrity

We treat documentation as code: an internal link check validates every relative reference, and decisions are recorded in two ADR series (platform + architecture).

  • 0 broken internal documentation links (117 checked across the repo).
  • 26 decision records (ADRs); new changes have to cite the right series.
  • 99 documentation files in docs/, including a solid onboarding guide (CONTRIBUTING.md).
  • A documentation clean-up in 2026 moved the wording from a legacy event store to the current PostgreSQL/Marten default (ADR-013): 142 → 109 mentions, and the rest are deliberate (history, opt-in mechanics, configuration).
  • No loose TODO/TBD markers in the documentation (only the repo name TBD-APS is a false positive).

We commit to measuring every web surface. Status as of 12-09-2026:

The untested surfaces are thin views: their real logic lives in shared, tested modules (status taxonomy, projections, API contracts). Page-specific render tests would be brittle with little benefit, so they are deliberately not written. We reassess when a surface gets real logic.

Known gaps, stated openly

Self-validation is only worth something if it shows what went wrong. Right now these items are open:

  • The Cloudflare Pages deploy is red on main (as of 12-09-2026). The deployment of that web surface fails in CI while the fix is worked on in a separate branch (fix/cloudflare-factory-isolation). We have chosen to show it, not hide it.
  • Coverage gaps in Contracts (24.9 %) and the PostHog adapter (6.4 %).
  • 8 thin web surfaces without page-specific tests (see above).
  • Unused projects: a Cosmos project has no references or tests and is a candidate for removal.

Our approach is to close gaps in order of priority, not to claim there are none. This artefact is updated when the numbers change.
