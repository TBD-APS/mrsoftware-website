# Public feature showcase

The homepage's managed “See live features” link opens `/demo/#try-features`.
The existing demo centre now starts with four specific tasks, followed by the
existing read-only product views. All new cross-page destinations belong to
`data/links.json` and its generated public module, including each feature's CTA.

The report example uses the generated public-roadmap SVG and links to its real
dashboard/downloads. It describes published feature counts, with no customer
activation or savings claim. Its phone preview reuses the compact SVG already
generated by the shared renderer for the same snapshot. Product examples link through the existing company
redirects to the working commercial demos. Their fictional data, browser-local
changes and Reset demo action are explained before the three guides.

The guides use actions already present in the deployed examples: Workslip's two
checks and Save time, Tradey's Approve offer and generated order, and Shippy's
receiver field and Complete delivery. They make no claim that a demo action
contacts a customer, places a real order or updates a live shipment.

`tests/commercial-ux/showcase.pw.mjs` follows the homepage entry, downloads and
checks the actual report workbook, then completes all three guides against the
local commercial application. It verifies the real company redirects while
mapping their external destinations to loopback. Network requests to production
are blocked. The normal `npm test` gate runs this journey on desktop and phone.

For future additions, choose one concrete visitor task with a working public
destination, name the input and visible result, and label its data accurately.
Check the task in a browser before adding it to the showcase. Private dashboard
snapshots and unconfigured provider integrations are not showcase inputs.
